# Journal-paper cases, chain vs i.i.d. vs threshold, held out

Generated by `SolarSimulator/Scripts/generate_journal_chain_sweep_configs.py --tune penalty`.
Every case of the Journal of Aircraft paper (`configs/final_journal_configs/`) is re-run with
the Markov-chain wind formulation added, under the standard year-split hold-out: the solver
is fitted on 1950–2002 and episodes are bootstrapped from 2003–2022.

## Cases

| Sweep | Swept | Fixed | Site |
|---|---|---|---|
| capacity | battery 100–600 Wh (11) | 3000 stages, penalty 5, start 06-10 | lat 30, lon −75 |
| duration | horizon 1000–27000 stages (8) | 300 Wh, penalty 20, start 01-01 | lat 30, lon −75 |
| penalty | failure penalty 0–100 (10) | 300 Wh, 3000 stages, start 06-10 | lat 30, lon −75 |
| location | lat 30 to −30 (7) × battery 100–600 Wh (11) | 3000 stages, penalty 10, start 01-01 | lon −25 |
| startdate | Jan/Mar/May/Jul/Sep 1 (5) | 300 Wh, 8500 stages, penalty 15 | lat 30, lon −75 |

Every site is over open ocean. The paper ran its location sweep along lon −75, where
lat 20 to −10 fall on land (eastern Cuba, Colombia, Ecuador, Peru; about 1 m/s mean wind
against 5–7.5 m/s offshore). This sweep moves it to lon −25 in the open Atlantic, where
every latitude is at least 300 km from land (Natural Earth 10 m coastline). The generator
refuses to write a site that is on land or within 100 km of a coast. lat 30, lon −75,
used by the other four sweeps, is 440 km offshore.

The paper's threshold-sweep case (300 Wh, 3000 stages, penalty 5, start 06-10) is the 300 Wh
cell of the capacity sweep, whose threshold arm runs the paper's full 7 × 5 grid. The duration
sweep is the union of the paper's two duration configs.

## Arms

All arms run 10,000 episodes on historical bootstrap weather (7-day blocks), with identical
weather and crash draws episode-for-episode.

- `iid`, `chain`: optimal policies solved without and with the 4-bin quantile wind chain.
- `thresh`: a 7 × 8 observation × wind threshold grid (observation 0–0.3 in steps of 0.05;
  wind 0, 3, 4, 5, 6, 8, 9, 12 m/s). It is the paper's threshold-sweep grid plus the wind
  thresholds the other paper sweeps used (4, 5, 8 m/s), so every combo any paper sweep ran
  is included. `compare_chain_sweep.py` takes the best of the 56 combos in each cell as the
  benchmark.

Picking the best of 56 combos on the same episodes it is scored on flatters the threshold
slightly, which makes the comparison conservative for the optimal arms. The comparison
reports a split-half check (pick on even episodes, score on odd) to show the size of that
effect; the October hold-out found it under 0.5 reward in every cell. The split-half check
only measures luck in the pick: both halves are evaluation years, so it cannot show the
advantage of tuning on the evaluation era's climate, which the optimal arms never see.
The `thresh_tune` arm removes both: it runs the same grid on the fit years, the combo is
picked there and scored on the evaluation episodes. `--tune` adds it to every sweep;
`--tune penalty` (or other sweep names) adds it only to those.

This directory was generated with `--tune penalty` (34 configs): the penalty sweep has the
tuning arm, since its high-penalty cells are where chain and threshold are within about
1 reward of each other.

34 configs, 222 optimal solves, 6,776 threshold simulations (560 of them the penalty tuning arm).

## Run

From `SolarSimulator/` in the pvlib conda env. Write results **outside OneDrive** with a short
path: value-table paths inside the OneDrive repo exceed the Windows 260-character limit, and
the runner refuses to start if they would.

```bash
python Scripts/run_chain_sweep.py --configs ../configs/journal_chain_sweep --out C:/Users/bepstein8/sim_results/journal_chain_sweep --resume
python Scripts/compare_chain_sweep.py --results C:/Users/bepstein8/sim_results/journal_chain_sweep --manifest ../configs/journal_chain_sweep/chain_vs_iid_sweep_manifest.json --verify
```

`--resume` skips configs that already finished, so an interrupted run can be restarted.
Provisioning runs first: it downloads any missing site record from Open-Meteo (serially,
waiting out the archive API's per-minute limit), then builds each site's fit-years table,
wind chain and evaluation cube, one process per site. Seven sites provisioned on this
workstation in 595 s on 2026-10-24; once a site is provisioned, a rerun only checks its files.

## Time estimate (this workstation, 23 workers)

From `Scripts/estimate_sweep_runtime.py`, calibrated on this machine with 10,000-episode
probes. On two full-size configs it overestimated by 14 % and 60 %, so read it as an upper
bound.

| Part | Estimate |
|---|---|
| Provisioning | done (lon −75 sites 2026-10-24, lon −25 sites 2026-10-25) |
| location sweep | 1.4 h |
| duration sweep | 0.8 h |
| startdate sweep | 0.3 h |
| capacity sweep | 0.2 h |
| penalty sweep | 0.2 h |
| **Total** | **about 2.8 h** |

Output is about 110 MB per config, roughly 5–6 GB in all. Re-estimate after any change with:

```bash
python Scripts/estimate_sweep_runtime.py --configs ../configs/journal_chain_sweep
```

## Variants

The estimates above use 10,000 episodes for every simulation, optimal and threshold alike.

- `--native` adds iid/chain runs in their own synthetic world for the calibration columns:
  about +1.6 h (measured before the threshold grid grew from 35 to 56 combos).
- `--episodes 3000` cut the simulation estimate from 2.4 h to about 1.6 h with the 35-combo
  grid, at the cost of the sample
  size discussed in `Scripts/episodes_needed.py`. The probe is calibrated on 10,000-episode
  batches, which are cheaper per step, so this figure is slightly low.
